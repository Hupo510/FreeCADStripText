# 通用删除 STEP 模型上的 LCEDA / EasyEDA 文字（零残留）

立创 EDA / 嘉立创的 3D 模型会把 `LCEDA  EasyEDA` 字样和云朵 logo 印在器件表面。
本目录的 `strip_text.py` 用 FreeCAD 自带的 `freecadcmd.exe`（无需图形界面）把文字
**连字形轮廓一起**清掉，同时保留原有配色和模型名。

```
29 个真实模型全量跑完：residue=0 × 29，isValid/isClosed × 29，
面积加权的配色分档 0 个丢失，颜色表结构 0 个问题，成品回扫 0 处残留。
```

**一句话说清关键设计**：删字**不用布尔运算**。布尔只要真的与实体相交，OCCT 就会
重建整个实体、把共面的配色小片合并掉 —— 表现就是"模型只剩一种颜色、整体变暗"。
改成**纯拓扑擦除**（删掉贴花面、从宿主面上摘掉字形内环、再把剩下的环拼回去）后，
其余每一张面和每一片配色都原样不动。

```bat
:: 只检测不改文件
strip_text.bat "C:\path\in.step" LIST

:: 确认后执行（省略输出路径时，写到输入同目录的 in_clean.step）
strip_text.bat "C:\path\in.step" "C:\path\out.step"

:: 路径带中文、空格、括号都可以，直接用
strip_text.bat "D:\Gizwits\PCB\260813.DY_4GC3_AI_Board(大有AI智能体)\3D\SOT-583-8_L2.1-W1.2-P0.50-LS1.6-BL.step"

:: 手工命令等价写法
"C:\Program Files\FreeCAD 1.1\bin\freecadcmd.exe" strip_text.py in.step out.step
```

> 中文路径曾经必崩（`surrogates not allowed`），原因与修法见 [3.1](#31-命令行带中文路径第-3537-条实测记录)。

可附加参数：`NAME=自定义名字`、`NOCOLOR`（不注入颜色）。
退出信息里 `[summ] ... residue=0` 就是零残留。

---

## 一、问题本质：不是浮雕，是"贴花"

文字并不是"从平面上凸出来的一块料"，而是**宿主平面上一片独立的面**，靠极薄的侧壁
贴在壳体上。实测到的四种形态：

| 形态 | 字面位置 | 宿主面上有字形内环 | 净体积 | 例子 |
|---|---|---|---|---|
| **A 凸起** | 平面外侧 1 µm | 有，环内是"岛面" | 正 | SIM-SMD 顶面 logo、CONN-TH 侧面 |
| **B 凹刻** | 平面内侧 1~10 µm | 有 | 负 | SIM-SMD 底面 LCEDA、CONN-SMD 底面 |
| **C 共面** | 与平面严格齐平（零厚度膜） | 有 | **0** | SOD-923 云 logo、TDFN-8 部分字 |
| **D 贴片实体** | 独立的薄壳实体，浮在壁面外 5~10 µm | 没有 | 正（很小） | LED-SMD_4P-L1.6-W1.5-TL 侧壁、SOD-882 |

### 为什么"用一个大立方体去削"必然失败

1. **矩形框** —— 立方体的侧面在平面上刻出一整圈新的棱线，这个框是刀具留下的，
   模型原本没有。
2. **字形线条** —— 字形轮廓是**宿主面自己的边界**（`Face.Wires` 里的内环）。
   布尔运算改变的是厚度，删不掉宿主面的边界，削薄之后轮廓线还在，甚至被重印一遍。
3. **C 型根本削不动** —— 零厚度的膜，`cut` 与它相交的体积是 1e-5 mm³ 量级，
   布尔算完它照样在那儿。

所以必须**先识别，再在极小范围内做精确动作，最后把碎片归并回去**。

## 二、算法：检测 → 判向 → 动刀 → 归并 → 复查

### 2.1 检测：三条线索，每一条都有闸门防误判

对每个实体、每个平面 `B`（面积 ≥ `min_host`）：

**线索 1 —— 宿主面上的"一簇小内环"**（`detect()`）

- 取 `B` 的内环（面积 < min(1 mm², 0.25·B.Area)），按包围盒距离 < `gap` 聚类，≥3 个算一簇；
- **闸门 ① 薄**：一簇在法向只能是 0.03 mm 以内的厚度（`thin_ok`），否则是"两层结构被误聚"；
- **闸门 ② 面积多样性**：这簇内环的面积必须"各不相同"（`distinct_areas(wa) ≥ 0.6·len(c)`）。
  字母形状不一 → 面积多档；焊盘开口 / 接触片 / 散热栅 → 面积只有一档。
  实测 WIFIM-SMD 底面 57 个内环只有 6 档（0.4 mm² 重复多次），那是 61 个邮票孔焊盘，
  不是文字 —— 这条闸门把它挡住了。

**线索 2 —— 平面两侧 ≤ 60 µm 处的一簇小面**（`detect()`，字面本体）

- 收集与 `B` 平行、偏移 `1e-7 < |off| ≤ 0.06`、投影落在 `B` 内的平面小面，聚类，≥4 个算一簇；
- **闸门 ③ 按偏移分档**：一簇里常混着"1 µm 深的字坑"和"严格共面的数值碎片"，
  若不分开，`min|off|` 被 0 拉平，整簇会被误杀（实测 WIFIM-SMD 的 44 个字坑就是这样丢的）；
- 每档再要求：`|off| ≥ 0.3 µm`、薄、面积和 ≤ `0.30·B.Area`；
- **接受条件二选一**：
  - (1) 宿主面上这个区域里确实有字形内环，且这簇小面**逐个正好盖住**某个内环
    （`rib_matches_wire`：平面内 bbox 尺寸比 0.55~1.15、中心偏移 ≤ max(0.03, 0.3·宽)）
    —— 铁证；
  - (2) 没有内环（文字是贴在完整平面上的"贴片"），但这簇面面积各档不同；
    等面积的一簇是同平面焊盘阵列，削掉会把器件削坏（实测 TDFN-8 底部 8 块
    0.09329 mm² 的焊盘被当成字面切走，整个模型只剩 14 个面）。

**闸门 ④ —— 实心形状阵列（这一条是补的，原来没有）**

就算这簇小面"逐个正好盖住某个内环"（看似铁证），只要它们自己是**等形状的实心块**，
它就是焊盘 / 测试点阵列，不是字：

- 判据 = **平面内填充率** `fill_ratio = 面面积 / 平面内包围盒面积`
  （矩形 = 1.000，圆 = 0.785；而任何字形只有 0.35~0.62，因为笔画只占字形外框的一部分）；
- 一簇 ≥ 6 个、且六成以上填充率 ≥ 0.75 → 判为阵列，拒绝。

为什么非加不可：老版本只靠"一簇面积和 ≤ 宿主 30%"拦这类东西，而
WIFIM-SMD_61P 的 61 个邮票孔焊盘实测 **39.9 vs 上限 37.0**，只差 8%。
擦除算法一改，成品上这 61 个面拆成 52+9 两簇、各自都过闸门（21.2 和 18.7），
回扫立刻报"残留 1 处"。同一类误判在 BULETM 与 ESP32-C3-WROOM-02 上一直是
**静默发生**的：两个模型的底面各有 9 个一模一样的 0.6×0.6 / 0.7×0.7 方块
（3×3 阵列，抬高 10 µm），老版本每批都把它们当字削掉 0.032 / 0.044 mm³ 的真焊盘。
换成形状判据后，这三处都判为阵列、一根面都不动。

**线索 3 —— 浮在壁面上的独立薄壳实体**（`detect_floating()`）

- "小实体的判据"：体积 ≤ 0.05 mm³、最小尺寸 ≤ 60 µm、最大尺寸 ≤ 0.8 mm；
- 这样的实体 ≥ 4 个聚在某个大平面的外侧 ≤ 60 µm 处，就算一簇；
- **超薄平板通道**：厚度 ≤ 5 µm 的平板不论横向多大都算贴花（`ultra_thin`）。
  真实结构件不存在 5 µm 以下的壁厚，所以哪怕它孤零零一个、凑不出"≥4 聚簇"，
  也只能是贴上去的字模。实测 WIFIM-SMD_ESP32-C3-MINI-1 的 EASYEDA 云朵 logo
  就是单独一个 1.38×1.01×0.001 的环状薄片（37 面），和 12 个字母相隔 0.25 mm，
  被"≥4 聚簇"漏掉，渲染图上那一朵云一直留在屏蔽罩上；
- **不限制"文字占宿主面多大比例"**。实测 LED-SMD_4P-L1.6-W1.5-TL 把字刻在
  1.62 × 0.28 的窄侧壁上，文字必然占掉大半个面，用 30% 的门槛会把整层字漏掉。
  判"是不是字"靠的是这些小实体本身又薄又轻，不是靠占比。

### 2.2 判向

看字面（或小实体中心）相对平面的偏移符号：

- 偏移在外侧 → **削**（A / D）
- 偏移在内侧 → **补**（B）
- 偏移为 0 → **只做拓扑重建，不动几何**（C）

### 2.3 动刀：C / D 型走拓扑擦除，只有 A / B 型才动布尔

**这一轮最大的改动，也是"颜色变单一、变暗沉"的真正元凶：不要用布尔运算去删字。**

`cut` / `fuse` 只要**真的与实体相交**，OCCT 就会把整个实体**重建**一遍，并把所有
共面的小片合并掉 —— 逐面配色正是靠这些共面小片撑起来的，于是整个模型塌回一种颜色。
实测 CONN-TH_2P-P2.00_HC-PH-2A-M：

```
原始 335 面 --cut 字的薄板--> 133 面   体积只差 0.0036 mm³(正好是字的体积)
原始 335 面 --cut 远处小方块--> 335 面  ← 不相交就一个面不少
```

也就是说**什么都没多切，但 200 多个面被合掉了**：元凶是"相交导致重建"，不是布尔
API 本身。全局 `removeSplitter()`（`ShapeUpgrade_UnifySameDomain`）是同一件事的
更激进版本 —— 同一个模型 335→111 面，218 个 `(0.25,0.25,0.25)` 面被吸进
`(0.10,0.10,0.10)`，看上去就是"颜色整体变暗"。**它已从流程里彻底删掉。**

替代方案 `erase_patch()`：**纯拓扑，不动几何**。

1. 用"字形内环指纹"定位宿主面（法向 + 平面内包围盒都要对得上）；
2. 删掉那些**平面内包围盒落在某个字形内环里**的贴花面（凸字的侧面 + 字面本体）；
3. 用**剩下的环**重建宿主面 —— 少了那几个内环，外环一个顶点都不动，
   所以这块面的颜色指纹（外环）仍然精确命中，能继承宿主色；
4. `Part.makeSolid(Part.makeShell(新宿主面 + 其余所有面))`；
5. 正、反两个法向各试一遍，取"闭合 + 有效 + 体积最接近原值"的那个。
   重建出来的面法向可能反了，只试一个方向会得到一个不闭合的壳。

结果：**一张面都不多不少**，其余所有面的配色小片原样保留。
实测 HDR-TH_10P 一次擦掉 11 处（1 块大侧壁 + 10 个针脚窄壁），面数 1498→684，
配色分档 `0.25:80% / 0.95,0.76,0.18:20%` 与源文件逐档对上。

**D 型（独立薄片实体）更简单**：直接从实体列表里摘掉那几个 solid，不做任何布尔、
也不 `removeSplitter`。早期版本拿薄板去 `cut`，薄板与壁面相切那一圈会把壁面切碎，
留下一圈矩形接缝（LED-SMD_4P-L1.6-W1.5-TL 实测 116 vs 122 面）。

**A / B 型（真凸起 / 真凹刻）才走布尔**，动作与保险如下。

| 形态 | 动作 | 刀 |
|---|---|---|
| A 凸起 | `cut` | 沿法向 0 → 字高+20 µm 的薄板 |
| B 凹刻 | `fuse` | 沿法向 −(字深+20 µm) → 0 的薄板 |
| C 共面 | `erase_patch` 重建宿主面 | 无布尔 |
| D 贴片实体 | 从 Solids 里摘掉 | 无布尔 |

薄板**只覆盖文字区域**（区域 = 这簇面的包围盒外扩 0.12 mm），厚度被限制在 0.06 mm
以内，所以**真墙、真柱、真通孔不可能被削坏**。薄板在**平面局部坐标系**里造
（`slab()`，用显式 `FreeCAD.Matrix` 搭正交基），所以 3~5° 的斜侧壁也能贴合。

五道保险（`act()` / `cut_clean()`）：

1. **体积上界**：去/补的料必须 `0 < dv ≤ 0.6 × 区域面积 × 板厚`；
2. **预期值校验**：`dv` 还必须落在"板∩实体体积"（削）或"板−实体体积"（补）的
   0.5~1.5 倍之内。OCCT 的布尔会**部分失败**（实测 SOD-923 的板明明盖住了云 logo，
   `cut` 只切掉 1/3 的字形，而体积守卫只看上界就放过了）；
3. **精确工具重试**：整块板判不过，就改拿 `板∩实体` / `板−实体` 当刀具，
   体积天然等于字的体积，不可能切过头；
4. **网格积分复核**：GProp 的 `Volume` 在布尔后的碎拓扑上会算错，
   两道都不过时用三角网格积分重算一遍；
5. **反复切到干净**：同一个实体、同一块板，OCCT 偶发"这次切掉了、下次没切掉"
   （`dv` 都在预期范围内，体积守卫看不出来）。所以每切一次就复查残留，
   不干净就重切，最多 3 次。

**扫膜补救**（A 型的兜底）：云 logo 这类零厚度膜，`cut` 有时会被保留下来。
把板往下多扎 1.5 倍字高再扫一次 —— 这个深度比 3D 打印精度还小一个量级，
装配和视觉上都等于没有，但字形轮廓确实没了。

### 2.4 归并：全局 `removeSplitter` 已废弃，改成"逐个面收内环"

老版本靠 `removeSplitter()` 把区域内被打散的共面碎片合并成一个整面，矩形印记
和字形轮廓线一起消失。它确实是**几何等价**的（`归并前.cut(归并后)` 与反向差都是 0），
但代价是**把配色小片一起合掉**（见 2.3 的 335→111 面）。

现在改用 `heal_region()`：调 `drop_inner_wires()`，一次只收一个面，循环 3 次。
它只删"没有对应贴花面的多余内环"，不合并任何面，配色分片因此原封不动。

只有在 `erase_patch` 失败、退回布尔兜底时才需要它；纯拓扑路径下不需要任何归并。

**布尔兜底还要再补一刀 `unify_patch()`**：布尔只要与实体相交，就会把宿主面上与刀口
相邻的共面小片重新分割，平面上留下一圈**字形轮廓接缝**。几何已经平了、颜色也对了，
但在显示棱线的查看器里"LCEDA"的轮廓仍然是一圈细线 —— 看起来像没删干净。
`unify_patch()` 只把「与宿主共面 **且** 落在文字区附近」的那几张面 `fuse` 起来再
`removeSplitter`，然后按"面积和相等 + 壳闭合 + 体积不变"校验后换回去，模型其它地方
一个面都不碰（绝不做全局 `removeSplitter`）。实测 CONN-TH_2P-P1.50 由 9 张并成 1 张
（73→65 面），背面彻底干净；CONN-SMD_HC-1.25-2PLT 8 张并成 1 张（153→145 面）。

### 2.5 复查：`residue=0` 是怎么判的

`audit()` 对每个候选，只看它自己那一层（`band_faces()`，按字高定范围、
按字形尺度定大小），要求：

- **平面外残面 = 0**：区域内、法向平行、偏移在 `1e-7 < |off| ≤ min(0.07, 1.6·字高+0.2µm)`、
  面积 ≤ 4×最大字形面积 的面，一个都不许剩；
- **字形内环 = 0**：宿主的那个平面上，区域内不许还有内环。

## 三、踩过的坑（每条都有实测数据）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 矩形框 + 字形线条 | 大立方体切割；字形轮廓是宿主面自身的边界 | 区域限定的薄板；后来整体改成拓扑擦除（`removeSplitter` 已废弃，见 18） |
| 2 | `removeSplitter` 后 `Volume` 变大 0.026，像"加了料" | GProp 在碎片拓扑上算不准 | 只认双向布尔差 + 网格积分，**不看 GProp 读数** |
| 3 | 小模型（SOD-882 / SOD-923）完全检不出 | `MIN_HOST = 0.8 mm²` 比整个模型还大 | `scales()` 按模型对角线自适应 |
| 4 | SOD-923 的板切不到字 | 宿主是 3.8° 的斜侧壁 | `slab()` 在平面局部坐标系里造盒子 |
| 5 | 板被转到别处、切不到任何东西 | `Placement(Rotation(axis, n))` 的轴向不确定 | 显式 `FreeCAD.Matrix` 搭正交基 |
| 6 | TDFN-8 底部 8 块焊盘被当字面切走，模型只剩 14 个面 | 等面积的一簇不是字 | `distinct_areas()` 面积多样性闸门 |
| 7 | WIFIM-SMD 底面 57 个内环被当文字 | 那是 61 个邮票孔焊盘，面积只有 6 档 | 同上 |
| 8 | WIFIM-SMD 的 44 个字坑整簇被丢 | 簇里混着共面碎片，`min|off|` 被 0 拉平 | 按偏移分档，逐档判定 |
| 9 | SOD-882 沿底面削掉 20 µm，少 0.0083 mm³ | 同一平面 60 µm 内还有器件底面/台阶面，`h` 取到最大值 | 只认"正好盖住字形内环最多"的那一层；残留判据的上界跟着 `offband` 走 |
| 10 | 同一个实体、同一块板，一次切掉一次没切掉 | OCCT 布尔对"与目标面严格相切"的刀具偶发部分失败 | `cut_clean()` 反复切 + 每次复查 |
| 11 | SOD-923 云 logo 切完还在 | 零厚度膜，`cut` 与它相交体积 ≈ 1e-5 mm³ | 往材料里扎 1.5 倍字高扫膜 |
| 12 | **`tessellate` 先跑过一次，后续布尔结果就变了** | OCCT 布尔结果会**原样复用**入参中未改动的面（同一个 TShape），而 `tessellate()` 把三角剖分写进那个 TShape；之后再拿同一实体做布尔就走"已有三角剖分"的快速路径 | 一切探测（预期值、网格体积）都在 `s.copy()` / `box.copy()` 上做 |
| 13 | LED-SMD_4P-L1.6-W1.5-TL 一个候选都没有 | 文字是**侧壁上的 13 个独立薄壳实体**，且占了窄壁 55% 的面积 | 新增线索 3 `detect_floating()`，且不限制占比 |

### 3.1 命令行带中文路径（第 35~37 条）实测记录

用户的实际命令（模型在 `D:\Gizwits\PCB\260813.DY_4GC3_AI_Board(大有AI智能体)\3D\`）：

```bat

进来以后 `sys.argv[2]` 是这样的（每个汉字 = 2 个孤立代理，`\udcb4\udcf3` 就是"大"的 GBK 两字节）：

```

  surrogate_at = [39,40,41,42, 45,46,47,48,49,50]
```

同一串的三种编码结果（`dev/c_enc.py` 实测）：

```
.encode('utf-8')                    -> UnicodeEncodeError: ... position 39-42: surrogates not allowed   ← 用户看到的报错
os.fsencode()                       -> b'...\xed\xb2\xb4\xed\xb3\xb3...'   CESU-8，路径根本不存在
.encode('utf-8','surrogateescape')  -> b'...\xb4\xf3\xd3\xd0AI\xd6\xc7...'  原始 GBK 字节，正确
```

所以修法是"**先还原字节，再按候选代码页重解**"：`utf-8` 严格优先（万一用户在 65001
控制台下跑），失败就按本地代码页（GBK/cp936）解。还原出的中文路径再交给
`Shape.read()` / `Import.export()` 就一切正常（`SOT-583-8` 走完：`residue=0`、
`dV=-0.000143`、69 面、颜色覆盖式注入成功）。

顺带三个坑：路径里带重复分隔符（`D://a//b.step`）时 `os.path.exists()` 说 True，
OCCT 的 `Shape.read()` 却报 `Error in reading STEP` —— 入口统一 `os.path.normpath()`；
脚本**自然结束**时 freecadcmd 仍会自己抛一次异常（打印
`Application unexpectedly terminated`、退出码非 0，其实文件已经写好了），所以结尾必须
`sys.exit()`；另外打印缓冲会随那次崩溃一起丢掉 —— 不加显式 flush 的话，看起来就是
"什么输出都没有"。


第 12 条最隐蔽，值得单独记一笔。实验（`dbg20.py`）：

```

## 四、颜色：照原文件的结构写回去

1. **解析**：读原 STEP 的 `STYLED_ITEM` 与 `OVER_RIDING_STYLED_ITEM`（后者才是逐面覆盖色），
   顺着
   `PRESENTATION_STYLE_ASSIGNMENT → SURFACE_STYLE_USAGE → SURFACE_SIDE_STYLE
   → SURFACE_STYLE_FILL_AREA → FILL_AREA_STYLE → FILL_AREA_STYLE_COLOUR → 颜色`
   拿到 RGB。整壳上色与逐面上色分两轮，**逐面优先**。

   两个**必须**遵守的语义细节（29 个模型里 28 个都用到了，不遵守就是"颜色被篡改"）：

   - **颜色实体不止 `COLOUR_RGB` 一种**。立创的导出件大量使用 ISO 10303-46 的
     `DRAUGHTING_PRE_DEFINED_COLOUR('black' / 'white' / 'yellow' …)`。不认识它，
     这些面就解析不出颜色、静默退回"实体基础色"——实测 BULETM 有 **223 个 black
     面 + 23 个 white 面**（白色屏蔽罩 + 黑色阻焊）全部变成金色，正好是用户截图里
     "两处颜色改变"；CONN-SMD_5P 有 436 个 black + 133 个 white 面同样被吞。
     现在按 8 色枚举表换算成 RGB 再写回。
   - **一个 `PRESENTATION_STYLE_ASSIGNMENT` 里可能同时有填充色和棱边色**：
     `((SURFACE_STYLE_USAGE(…白色…), CURVE_STYLE(…,#COLOUR_RGB 0.098)))`。
     `CURVE_STYLE` 是**棱边**颜色，不是面的颜色。老代码碰到预定义色解析不出来就继续
     遍历，一路走到 `CURVE_STYLE` 的深灰上，于是"白色/银色侧块"被写成深灰
     （用户描述的"变暗沉"）。现在先只走 `FILL_*` 这一支，实在没有填充色才退回任意颜色。
2. **映射**：清理后导出、再读回（读回的面顺序 = 文件里 `ADVANCED_FACE` 的顺序），
   用三把指纹把新面匹配回原面：
   - 主指纹「中心点 + 面积」—— 没被动过的面精确命中；
   - 副指纹「**外环**（`OuterWire` 的包围盒）」—— `erase_patch` 重建宿主面时外环
     一个顶点都不动，只是少了几个内环，所以面积和中心都变了，只有外环还能精确命中。
     没有这一把，被补平的那块面会掉进"就近继承"。
   - 第三把「**同平面宿主**」—— 布尔补平/削平后新生成的面，与宿主面**共面**
     （法向 + 平面偏移都相同），而字形侧壁是竖直的、字形底面差一个字深，都不在同一
     平面。所以按 `(法向, 偏移)` 找源面，取"在平面内包围住它、且不比它小"的那张里
     最贴身的。**这一把不能省**：老版本对这类面走"最近的面"，于是补平后的区域
     继承了字形的深灰，整个文字区变成一块深色矩形 —— 看起来就像文字根本没删掉
     （CONN-TH_2P-P1.50 背面的 LCEDA 就是这种形态：凹陷 10 µm、深灰）。
   故意**排除被判为文字的面**，这样补平后的面继承宿主色而不是字色。
3. **注入**：结构与原文件**同构** ——
   - 每个实体一条整体 `STYLED_ITEM('color',(#base),#MANIFOLD_SOLID_BREP)`；
   - 每个面一条 `OVER_RIDING_STYLED_ITEM('overriding color',(#psa),#face,#ref)`；
   - 全部登记进 `MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION`。

> **两个致命细节（任一写错，模型就只剩一种颜色、而且偏暗）：**
>
> 1. 第 4 个参数 `over_ride` 必须是**单个** `#id`，不能写成集合 `(#id)`。
>    原文件是 `...,#245,#52905);`，早期版本写成 `...,(#17),(#3243));` ——
>    严格的解析器会把整条覆盖项丢掉，于是所有面退回基础色（= 出现次数最多的那档，
>    往往是深灰），这就是用户看到的"单一颜色 + 变暗沉"。
> 2. 每张面的覆盖项要引用**它自己那个实体**的基础 `STYLED_ITEM`；多实体模型里
>    6 个实体 6 条基础项，各引各的。全部指向第一个实体的基础项，多实体模型会串色。
>
> 结构校验器 `stylecheck.py` 会逐条检查这两点（`over_ride` 是不是集合、是不是
> 单个 id、有没有指向 `STYLED_ITEM`），29 个成品全部 0 问题。

- 差异块的 Z 区间全都落在两个文字平面 ±2 µm 内，**文字区之外一个面都没动**。

渲染核对在 `render/` 目录（`r3d.py` 用软件渲染 + 消隐棱线叠加）。
**必须看棱线**：普通着色渲染看不出残留，残留的表现形式就是那几根多出来的棱线。

## 六、已知限制与安全边界

- **宁可不动，不可动错**：任何一步体积校验不过就回滚。看到
  `去料异常, 回滚` / `补料异常, 回滚` 说明这一处没改，模型仍然是好的。
- **会主动拒绝的几类东西**（都写过误判事故，见第三节 6/7/29/30）：
  等面积的焊盘阵列、邮票孔 / 半孔阵列、实心方块组成的测试点阵列、
  散热栅、以及和宿主面严格共面的数值碎片。
- **纯拓扑路径不改几何**：`erase_patch` 只删面、只删内环，一点也不动顶点，
  所以几何上除了"字形本身没了"之外没有任何位移 —— 这也是它不会破坏配色的原因。
- **文字必须落在平面上**：曲面上（圆柱、圆角）的字不做处理。
  这类导出件几乎全是平面贴花，真碰上曲面文字会打印"非平面, 跳过"。
- **`LIST` 先看再改**：会列出每个候选的宿主面面积、平面、内外侧、区域。
- 文字区域若跨过通孔，补料守卫会因体积异常而回滚，属于安全失败。
- 颜色注入是**按指纹重建**的，不是原样拷贝：文字被填平后，那块面会继承宿主面的
  颜色（外环指纹，或"同平面宿主"指纹）。如果原来文字是深色、宿主是浅色，填平后
  那块就是浅色 —— 这正是我们想要的。
- 布尔兜底会在刀口边缘留下个别 ≤0.002 mm² 的退化碎面（1 µm 高的侧条），
  `colordiff.py` 会把它们报成"未匹配"（配不到源面），视觉上不可见；
  纯拓扑路径不会产生这种碎面。
- 逐面覆盖色依赖"面顺序"假设（`ADVANCED_FACE` 的书写顺序 = 读回顺序），
  已用 `OVER_RIDING_STYLED_ITEM` 里显式引用 `#面` 的写法，不依赖顺序猜色。
- 多实体模型（如 SIM-SMD 2 个、LED-SMD_4P-L2.0-W2.0-BR 6 个）每个实体各写一条
  基础 `STYLED_ITEM`，覆盖项引自己那条；`stylecheck.py` 会校验。

## 七、目录里都有什么

| 文件 | 作用 |
|---|---|
| `strip_text.py` | 主脚本：检测 / 判向 / 拓扑擦除（或布尔兜底）/ 复查 |
| `colorize.py` | 颜色解析、三指纹映射（中心+面积、外环、同平面宿主）、覆盖式注入 |
| `stepcolor.py` | STEP 文本解析（实体拆分、参数拆分、颜色链、8 色预定义表、填充色优先） |
| `batch.sh` | 批量跑 `C:\Users\lhm\Downloads\*.step`，输出到 `out/` |
| `strip_text.bat` | Windows 下的一行封装 |
| `r3d.py` / `rcol.py` / `renders.py` | 软件渲染 + 逐面配色 + 消隐棱线，前后对照 |
| `r2.py` | 单模型同视角前后对比渲染（`B=<主干> V=<视角> [Z=xmin,..,ymax]`） |
| `rcmp.py` | 多模型批量前后对比渲染 |
| `resweep.py` | **成品回扫**：拿文字检测器再审一遍成品，应为 0 处 |
| `colorarea.py` | 面积加权的配色分档对比（面数会被贴花的碎面带偏） |
| `colordiff.py` | **逐面**配色对比：按几何把成品每张面配回源面再比色，只报"真的变色"的那几张 |
| `stylecheck.py` | 注入的颜色表结构校验（`over_ride` 单 id、基础项归属） |
| `verify_all.py` | 成品批量校验：回读 valid/closed、颜色链条数、产品名是否退化 |
| `colorstat.py` / `chk.py` / `colorchk.py` / `audit2.py` | 按颜色分组核对、双向布尔求差、拓扑复查 |
| `dev/` | 调试探针（`dbg*.py`、`c_*.py` 等）。`c_logo.py` 定位云朵 logo、`c_61p.py` / `c_61p2.py` 对比焊盘阵列判定、`c_dbg.py` 配合 `DEBUG_DETECT=1` 打印每道闸门的实测值 |

`strip_text.py` 支持 `LIST` 参数只列候选不动刀；环境变量 `DEBUG_DETECT=1`
会把每一簇小面过闸门时的实测值（面数 / 命中内环数 / 面积和 vs 上限 / 实心面数 /
是否判为图案 / 区域）全部打出来，调阈值时不用猜。
